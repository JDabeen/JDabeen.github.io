**반별 숙제공지 작성 약 30분 → 3분 이내. 동료 강사들이 실제 업무에 사용 중입니다.**

**[프로그램 직접 체험하기](https://jdabeen.github.io/homework-automation-demo/)**

**개인 프로젝트** · Python·Colab 시제품 → HTML·CSS·JavaScript 단일 웹앱 · GPT·Claude 개발 보조

## 프로젝트 요약

| | |
| --- | --- |
| **문제** | 교재·진도마다 숙제 범위와 음원 링크를 매번 수작업으로 확인 |
| **해결** | 교재별 규칙과 음원 정보를 구조화해 공지 자동 생성 |
| **현장 적용** | 설치 없이 실행하도록 변경하고, 동료 피드백을 반영해 실제 도입 |
| **담당 역할** | 업무 분석·규칙 정리·요구사항 반영·출력 검증·현장 적용 |

> 시간 단축 수치는 직접 수행한 업무의 전후 체감 소요시간 기준이며, 통제 실험 결과는 아닙니다.

## 1. 무엇이 문제였나

학원에서는 수업이 끝날 때마다 교사가 숙제공지를 직접 작성했습니다. 숙제 범위는 교재·레벨·Unit·학습 일차마다 달랐고, 본문·Q&A·Vocabulary·Interpreter 등의 음원 트랙과 링크도 확인해야 했습니다.

핵심 문제는 공지 문장을 쓰는 일이 아니라, **흩어진 정보를 매번 찾아 조합하는 일**이었습니다.

- 계획표에서 수업 일차에 맞는 **숙제 페이지** 확인
- 본문·Q&A·Vocabulary·Interpreter의 **녹음 과제 및 음원 링크** 연결
- Review Day, 일부 Unit의 트랙 번호, 촬영 과제 등 **예외 규칙** 반영

교재·Unit·일차가 정해지면 결과 대부분이 결정된다는 점에 착안해, 반복 작업을 규칙으로 분해했습니다.

## 2. 어떻게 만들었나

### ① 업무 규칙을 데이터로 분리

교재와 수업 일차를 키로 삼아 숙제 페이지, 녹음 항목, Interpreter 범위 등을 구조화했습니다. 원본 프로그램에는 **Basic 12권·Intermediate 12권(각 4개 Unit)**과 **Foundation 30권**의 과정별 규칙이 들어갑니다.

기본 숙제 범위는 자동으로 채우되, 수업 상황에 따라 **강사가 직접 수정**할 수 있게 했습니다.

### ② 음원 매칭과 예외 처리

레벨·교재·Unit·트랙 번호로 음원을 찾도록 했습니다. **일치하는 파일이 정확히 하나인지 검사**하고, 누락·중복은 오류로 표시해 잘못된 링크가 조용히 선택되지 않도록 했습니다.

- Basic: 교재별 Unit에 따라 본문·Q&A·어휘 트랙 매칭
- Intermediate: Unit에 따라 음원 Part 구분 및 일부 교재의 트랙 번호 예외 적용
- Foundation: Phonics·Phonics Story·Story·Chant 음원 구분
- 특수 일차: Review Day, Sentence Build-up, 교구촬영, 녹음 과제 등 규칙 반영

### ③ Colab 시제품에서 단일 HTML로 전환

Python·Google Colab에서 먼저 로직을 구현했습니다. 하지만 동료들이 개발 환경을 다뤄야 한다면 현장 도입이 어렵다고 판단했습니다.

이후 HTML·JavaScript 기반 **독립 실행형 단일 파일**로 전환했습니다. 교재별 데이터와 규칙을 파일 내부에 포함하므로, 공지 생성 과정에서는 외부 API나 인터넷 연결이 필요하지 않습니다. 다만 생성된 실제 음원 링크를 열 때는 인터넷이 필요합니다.

### ④ 실제 사용자 피드백을 반영

처음에는 새 도구 사용을 부담스러워하는 동료들도 있었습니다. **입력 방식, 기존 공지와의 문구 차이, 과제 누락 여부**에 대한 의견을 듣고 수정했습니다.

반·교재·일차 선택 → 숙제 자동 입력 → 공지 생성 → 전체 복사라는 기존 업무 흐름을 최대한 단순하게 만들었습니다. 이후 **수업 시작·종료일, 다음 레벨 예상일, 전체 숙제 계획표 확인**과 같은 운영 보조 기능도 추가했습니다.

## 3. 어떤 점을 검증했나

운영 버전에서는 **음원 매칭·일차 규칙·특수 Unit·Review Day**를 검사했습니다. Colab과 HTML에서 생성한 공지 내용도 비교했습니다.

공개 체험판은 원본 화면과 주요 흐름을 유지하고, **가상 데이터로 별도 검증**했습니다.

- Basic 12권 × 4개 Unit의 본문·Q&A·어휘 샘플 트랙 매칭
- Intermediate 12권 × 4개 Unit의 샘플 트랙 매칭
- Foundation 30권의 학습 일차 및 Phonics·Story 음원 구분
- 샘플 숙제 계획 자동 입력, 공지 생성, Review Day, 결과 복사

※ 위 체험판 테스트는 **가상 데이터 기준**입니다. 운영 원본의 내부 데이터는 공개하지 않습니다.

## 4. 실제 프로그램과 공개 데모의 차이

| 구분 | 운영 프로그램 | 공개 체험판 |
| --- | --- | --- |
| 화면·조작 방식 | 원본 UI | **원본 UI 유지** |
| 과정 구분 | Basic / Intermediate / Foundation | 동일 |
| 교재별 숙제 데이터 | 학원 실제 자료 | **가상 페이지·가상 학습 내용** |
| 음원 링크 | 운영용 Drive 음원 링크 | 샘플 링크 **1개만 표시**, 나머지 비공개 |
| 내부 식별정보 | 포함 | **제거** |

원본 HTML·음원 DB·교재별 실제 계획표는 학원 내부 자료를 포함하므로 공개하지 않습니다. 체험판에 있는 가상 자료는 원본 교육 내용이나 음원을 재현한 것이 아닙니다.

## 5. AI를 어디에 사용했나

GPT·Claude는 코드 작성과 수정, 테스트 케이스 구성 등을 돕는 **개발 보조 도구**로 사용했습니다. 어떤 업무를 자동화할지 정의하고, 현장에서 필요한 규칙과 사용 흐름을 판단하고, 생성 결과를 확인해 개선하는 일은 직접 수행했습니다.

**실제 숙제공지 생성에는 AI 모델을 호출하지 않습니다.** 입력값과 정리된 규칙에 따라 JavaScript가 결정적으로 결과를 생성합니다.

기능을 만드는 것에서 끝나지 않고, **실제 사용자가 기존 업무에서 계속 쓰도록 만드는 것**까지가 해결 과정이라고 생각합니다.
